# Development Principles

- Keep personal solution history local.
- Treat imported problem statements as external, reproducible generated data.
- Derive topic labels from the current catalog; do not invent a partial taxonomy.
- Record source or storage-policy changes in `DECISIONS.md`.
- Keep authored learning blocks concept-led, accessible without motion, and
  separate from imported catalog content.
- Treat learner input and interaction history as Personal local state; do not
  render, commit, log, or use it as a public mastery indicator.
- Bind any local execution viewer only to `127.0.0.1`; never describe it as a
  sandbox or send code, test data, or results to a remote service.
- Present runner timing only as a local relative measurement. Keep public
  solution research link-only and use original local implementations to compare
  approaches.
